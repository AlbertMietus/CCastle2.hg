``castle.readers.support.Stack`` — Bug & Analysis
===================================================

.. error::

   **Bug in** ``castle/readers/support/__init__.py``

   The module imports from ``.support``, but the file is named ``stack.py``::

       from .support import Stack   # WRONG: no module named 'castle.readers.support.support'

   **Fix:**::

       from .stack import Stack

   This causes a ``ModuleNotFoundError`` at import time, but is currently **never triggered**
   because ``Stack`` is not yet used anywhere in production code or tests.

Why the bug was not caught
--------------------------

``Stack`` was added as infrastructure for future use, likely anticipating a parser-stack
inside the TatSu action handlers. However:

* ``Stack`` is **not imported** anywhere in production code.
* ``Stack`` is **not imported** anywhere in the test suite.
* There is **no smoke-test** that simply does ``from castle.readers.support import Stack``.

Because nothing triggers the import of ``castle.readers.support``, the ``ModuleNotFoundError``
is never raised — not during tests, not at runtime.

The TDD pattern (test first, then code) was not followed for this class. The class was
generated by a CodeAI tool and committed without a test, which masked the typo in ``__init__.py``.

What needs to be done
---------------------

#. **Fix the bug** in ``castle/readers/support/__init__.py``:

   .. code-block:: python

      # Before (wrong):
      from .support import Stack

      # After (correct):
      from .stack import Stack

#. **Add a test** — at minimum a smoke-test that imports ``Stack`` and verifies basic behaviour:

   .. code-block:: python

      from castle.readers.support import Stack

      def test_Stack_import():
          s = Stack()
          assert s.is_empty()

      def test_Stack_push_pop():
          s = Stack()
          s.push(1)
          assert not s.is_empty()
          assert s.pop() == 1
          assert s.is_empty()

#. **Decide** whether ``Stack`` is still needed. The 6-day gap after commit 1061
   and the absence of any usage suggest the parser-stack idea may have been abandoned.
   If so, consider removing the class entirely.
